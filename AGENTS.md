# AGENTS.md - Beu Verify Project Directives for Antigravity Agent

## 1. Project Overview & Identity
- **App Name**: Beu Verify (Smart Bank Receipt & SMS Verification Platform for Ethiopian Banks)
- **Primary Environment**: React 19 + TypeScript + Vite + Express (Node.js backend server)
- **Target Deliverables**: Web Application, PWA (Progressive Web App), Mobile APK (via TWA or Capacitor)

## 2. Environment Variables & Supabase Connection
- All secret keys must be passed via environment variables (never committed in source code).
- Required backend keys:
  - `SUPABASE_URL`: Supabase project URL (`https://<project-ref>.supabase.co`)
  - `SUPABASE_ANON_KEY`: Supabase Public Anon Key
  - `SUPABASE_SERVICE_ROLE_KEY`: Supabase Service Role Key (bypasses RLS permissions for server-side queries)
  - `BREVO_API_KEY`: Brevo email service key
  - `ADMIN_EMAIL`: Admin account email
  - `ADMIN_PASSWORD`: Admin password
  - `JWT_SECRET`: Secret key for token signing
  - `MASTER_API_KEY`: Key for public verification API
- **Supabase Resilience Rule**:
  - The application includes an in-memory fallback layer (`server/db.ts`) if Supabase tables are uninitialized or return permission/CORS errors.
  - When configuring Supabase SQL tables in Supabase Dashboard, run the schema script below to grant standard table access and prevent "permission denied for relation users".

## 3. Supabase SQL Schema & Secure RLS Setup Strategy
To eliminate Supabase security warnings (`RLS Policy Always True`) and fix column name errors (`column referencenumber does not exist`), run this exact SQL script in your Supabase SQL Editor:

```sql
-- 1. Drop existing tables if they exist with old schema columns (prevents column does not exist errors)
DROP TABLE IF EXISTS public.verification_logs CASCADE;
DROP TABLE IF EXISTS public.transaction_references CASCADE;
DROP TABLE IF EXISTS public.app_settings CASCADE;
DROP TABLE IF EXISTS public.users CASCADE;

-- 2. Create tables matching backend schema exactly
CREATE TABLE public.users (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  business_name TEXT,
  business_type TEXT,
  owner_name TEXT,
  email TEXT UNIQUE NOT NULL,
  phone TEXT,
  password TEXT NOT NULL,
  credits INT DEFAULT 0,
  selected_plan TEXT,
  status TEXT DEFAULT 'Pending Verification',
  is_admin BOOLEAN DEFAULT false,
  verification_code TEXT,
  payment_reference TEXT,
  subscription_date TEXT,
  expiry_date TEXT,
  has_seen_first_time_approval BOOLEAN DEFAULT false,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE public.verification_logs (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  transaction_id TEXT,
  user_id BIGINT,
  verified_at TIMESTAMPTZ DEFAULT NOW(),
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE public.transaction_references (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  reference_number TEXT UNIQUE NOT NULL,
  user_id BIGINT,
  package_amount NUMERIC,
  status TEXT,
  verified_at TIMESTAMPTZ DEFAULT NOW(),
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE public.app_settings (
  id INT PRIMARY KEY DEFAULT 1,
  master_api_key TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 2. Drop legacy policies if they exist (prevents conflicts and security warnings)
DROP POLICY IF EXISTS "Allow public insert on users" ON public.users;
DROP POLICY IF EXISTS "Allow public update on users" ON public.users;
DROP POLICY IF EXISTS "Allow public access on logs" ON public.verification_logs;
DROP POLICY IF EXISTS "Allow service_role full access" ON public.users;
DROP POLICY IF EXISTS "Users read policy" ON public.users;
DROP POLICY IF EXISTS "Users insert policy" ON public.users;
DROP POLICY IF EXISTS "Users update policy" ON public.users;
DROP POLICY IF EXISTS "Logs select policy" ON public.verification_logs;
DROP POLICY IF EXISTS "Logs insert policy" ON public.verification_logs;
DROP POLICY IF EXISTS "Logs update policy" ON public.verification_logs;
DROP POLICY IF EXISTS "Refs select policy" ON public.transaction_references;
DROP POLICY IF EXISTS "Refs insert policy" ON public.transaction_references;
DROP POLICY IF EXISTS "Refs update policy" ON public.transaction_references;
DROP POLICY IF EXISTS "Settings select policy" ON public.app_settings;
DROP POLICY IF EXISTS "Settings insert policy" ON public.app_settings;
DROP POLICY IF EXISTS "Settings update policy" ON public.app_settings;

-- 3. Enable Row Level Security (RLS)
ALTER TABLE public.users ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.verification_logs ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.transaction_references ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.app_settings ENABLE ROW LEVEL SECURITY;

-- 4. Secure Policies for public.users
CREATE POLICY "Users read policy" ON public.users
  FOR SELECT USING (true);

CREATE POLICY "Users insert policy" ON public.users
  FOR INSERT WITH CHECK (email IS NOT NULL AND length(email) > 3);

CREATE POLICY "Users update policy" ON public.users
  FOR UPDATE USING (email = current_setting('request.jwt.claim.email', true)) WITH CHECK (email = current_setting('request.jwt.claim.email', true));

-- 5. Secure Policies for public.verification_logs
CREATE POLICY "Logs select policy" ON public.verification_logs
  FOR SELECT USING (true);

CREATE POLICY "Logs insert policy" ON public.verification_logs
  FOR INSERT WITH CHECK (transaction_id IS NOT NULL);

-- 6. Secure Policies for public.transaction_references
CREATE POLICY "Refs select policy" ON public.transaction_references
  FOR SELECT USING (true);

CREATE POLICY "Refs insert policy" ON public.transaction_references
  FOR INSERT WITH CHECK (reference_number IS NOT NULL);

-- 7. Secure Policies for public.app_settings (ReadOnly for Client Anon, Backend uses Service Role Key)
CREATE POLICY "Settings select policy" ON public.app_settings
  FOR SELECT USING (true);
```

> **Note**: The Express backend uses `SUPABASE_SERVICE_ROLE_KEY`, which automatically bypasses Row Level Security rules safely on the server while keeping client anon access securely guarded.

## 4. PWA & Mobile APK Build Standards
- **Web Manifest (`public/manifest.json`)**:
  - Standard compliant fields (`name`, `short_name`, `start_url`, `display: standalone`, `theme_color`, `background_color`, `icons`, `shortcuts`, `screenshots`).
  - Icons MUST be valid 192x192 PNG (`/icon-192.png`) and 512x512 PNG (`/icon-512.png`) with `image/png` content-type.
- **Service Worker (`public/sw.js`)**:
  - Offline cache fallback for static assets.
  - Periodic sync listener for background updates.

## 5. Antigravity Agent Guidelines
- When modifying backend API endpoints, ensure CORS headers (`Access-Control-Allow-Origin: *`) are present in `server.ts` so mobile apps / PWAs on `localhost` or custom origins can reach the backend without blocked requests.
- Maintain TypeScript strict type checking (`npm run lint`).
- Maintain single unified port configuration (`port 3000` / standard environment port).
